# Animica 10.0.0 L2 — measured performance (dev box)

Hardware: shared dev host, 10 logical CPU cores, 31 GiB RAM, single SATA SSD,
CPython 3.12 (GIL). liboqs 0.14.0 ML-DSA-65 native backend active (verified
byte-equivalent to the chain's pure-Python FIPS-204 reference in both directions).

Command: `l2/bench.py` (see `animica l2 bench`). Conditions stated per row.

## Signature verification (the classic L2 bottleneck)

| backend | workers | verify/s |
|---|---|---|
| pure-python (chain oracle) | 1 | ~48 |
| liboqs (raw, standalone) | 1 | ~12,858 |
| liboqs via SignatureVerifier (cached path) | 1 | ~7,060 |
| liboqs via SignatureVerifier | 8 | ~4,827 |

Signing (ML-DSA-65): ~9.5 sign/s/core (~120 ms/op) — done client-side, off the
hot path.

## Execution + SMT + state (no crypto; unsigned)

| workers | exec TPS |
|---|---|
| 1 | ~9,139 |
| 8 | ~5,367 |

## DA compression (raw wire bytes / compressed blob)

| workload | compression |
|---|---|
| transfers | 2.67× |
| payments | 2.68× |
| inference micropayments | 2.66× |
| batch payouts (256 recipients/tx) | 6.75× |

BATCH_PAYMENT effective transfers/sec ≫ tx/sec: one signature + one nonce
authorizes N credits, so 100 batch txs = 25,600 effective transfers.

## The load-bearing finding: CPython is GIL-bound

Both the pure-Python executor and the liboqs verify binding are serialized by the
GIL (the oqs-python binding does not release it), so **thread-based parallelism
reduces throughput** on this stack. Single-worker is the practical optimum today.

- **Real sustainable single-core end-to-end ceiling ≈ min(verify 7,060/s, exec
  9,139/s) ≈ ~7,000 verified L2 TPS**, signature-verification-bound.
- The deterministic parallel executor is proven correct (identical roots across
  1/2/8/16 workers) and the worker-pool architecture is in place; it does not yet
  translate to multicore speedup on CPython.

### Path to horizontal scaling (architecture already supports it)

1. **Process-pool execution** with account-range sharding (components are already
   account-disjoint — the hard part is done; only cross-process state transfer
   remains). Projected: ~9k exec/s × cores.
2. **Free-threaded CPython (3.13+ `--disable-gil`)** — the existing thread pools
   would then scale; liboqs verify → ~12.8k/s × cores (≈128k verify/s on this
   10-core box, measured standalone).
3. **Native execution/verify core** (Rust/C) — removes the GIL entirely.

### Theoretical ceilings on this box

- Signature verify: 12,858/s/core × 10 cores ≈ **128k verify/s** (no-GIL/native).
- DA bandwidth: transfers compress to ~1.5 KB/tx wire → at 100 MB/s anchor
  bandwidth ≈ 65k tx/s DA-bound; batch payouts far higher per effective transfer.
- The lowest sustainable pipeline stage is the real system TPS — today that is
  signature verification under the GIL (~7k/s), which the scaling paths above lift.

# Chain Reset Guide

## Overview

This guide describes the Animica chain reset implemented on **2026-01-18** that restarts the blockchain from height 0 with a new genesis block.

## What Changed

### New Genesis Parameters
- **Genesis Hash**: `0x6a27e93193020cd00fe429ef0ffac1c3a774268a589c2911ac396dd3cba2d242`
- **Fork ID**: `0x823f8537`
- **Genesis Timestamp**: `2026-01-18T00:00:00Z` (Unix: 1768694400)
- **Genesis Message**: "Animica Chain Reset Jan 2026 - Quantum-Resistant Blockchain"

### Previous Genesis (Now Invalid)
- **Old Genesis Hash**: `0x5868b982d22fe2eb4eb15567dd6afdbae453001388bc23a2517639729428cfda`
- **Old Timestamp**: `2026-01-16T00:00:00Z`
- **Status**: **Rejected** - Nodes will refuse to start with old chain data

## Why Nodes Reject Old Data

The chain reset changes the genesis block hash, which is the foundation of the blockchain. All subsequent blocks reference the genesis directly or indirectly through their parent hashes. Key validation mechanisms:

1. **Genesis Hash Check**: Nodes validate that the database genesis hash matches the expected constant (`consensus/params.py::GENESIS_HASH`)
2. **Genesis Guard**: P2P and RPC layers check genesis hash at startup and refuse mismatches
3. **Fork ID**: Network handshake uses fork ID derived from genesis hash to prevent old/new network mixing
4. **Protocol Version**: Updated to ensure incompatibility with old chain

## For Node Operators

### Required Actions

All node operators **must** perform a chain reset to continue running nodes after this update.

### Step 1: Update Code

```bash
git pull origin main
# Or download the latest release
```

### Step 2: Reset Chain Data

#### Option A: Using CLI (Recommended)

```bash
# Stop node and wipe all chain data (keeps wallet addresses)
animica node reset --yes

# Or for specific network
animica node reset --network mainnet --yes
```

#### Option B: Manual Reset (Docker)

```bash
# Stop containers and remove volumes
docker compose down -v --remove-orphans

# For custom networks, also remove named volumes
docker volume ls | grep animica_mainnet
docker volume rm animica_mainnet_chain_0_<genesis_tag>_data
```

#### Option C: Manual Reset (Host)

```bash
# Remove chain data directory (mainnet example)
rm -rf ~/.animica/chain-0/

# Preserve wallet files if separate
# Wallet is typically at ~/.animica/wallets.json
```

### Step 3: Start Fresh Node

```bash
# Start node - will initialize with new genesis
animica node up

# Or
docker compose up -d
```

### Step 4: Verify Genesis

```bash
# Check that genesis hash matches
animica chain head
# Should show height: 0 initially

# Verify genesis hash in logs
docker logs animica_mainnet_node | grep -i genesis
# Should show: 0x6a27e93193020cd00fe429ef0ffac1c3a774268a589c2911ac396dd3cba2d242
```

## Data Loss Warning

⚠️ **CRITICAL**: Chain reset **permanently deletes** all previous chain data:

- ✅ **Preserved**: Wallet addresses and private keys (stored separately)
- ❌ **Lost**: All balances, transaction history, mining rewards, smart contract state

### Balance Backup (Optional)

The CLI reset command includes automatic balance backup:

```bash
# Backup balances before reset (default behavior)
animica node reset --backup-balances

# Backup file saved to: ~/.animica/chain-{id}_balances_backup.json
```

**Note**: Backed-up balances are for record-keeping only. They cannot be automatically restored on a fresh chain.

## For Developers

### Genesis Generation

The canonical genesis is generated by:

```bash
python consensus/build_genesis.py --verify
```

This produces `consensus/genesis_output.json` with deterministic hash based on:
- `consensus/params.py::GENESIS_TIMESTAMP_UTC`
- `consensus/params.py::GENESIS_MESSAGE`
- `consensus/params.py::GENESIS_THETA_MICRO`
- `core/genesis/genesis.json::alloc` (premine allocations)

### Testing Genesis Validation

Run the chain reset validation tests:

```bash
pytest test_chain_reset_validation.py -v
```

This verifies:
- New genesis hash matches expected constant
- Old DBs with wrong genesis are rejected
- Fresh DBs start at height 0
- Genesis parameters are consistent

## Troubleshooting

### Error: "GENESIS_MISMATCH"

**Symptom**: Node fails to start with genesis mismatch error

**Cause**: Database contains old genesis hash

**Solution**:
```bash
animica node reset --yes
animica node up
```

### Error: "genesis path does not match canonical network genesis"

**Symptom**: Genesis loader rejects genesis file

**Cause**: Using wrong genesis file for network

**Solution**: Ensure you're using the correct genesis file:
- Mainnet: `core/genesis/mainnet.json`
- Testnet: `core/genesis/testnet.json`
- Devnet: `core/genesis/devnet.json`

### Node won't start after reset

**Check**:
1. Verify genesis hash in logs matches `0x6a27e93193020cd00fe429ef0ffac1c3a774268a589c2911ac396dd3cba2d242`
2. Ensure all volumes/data directories were removed
3. Check for lingering containers: `docker ps -a`
4. Verify code is updated to latest version

### Peers won't connect

**Symptom**: Node can't find peers after reset

**Cause**: Network fork ID changed

**Solution**: 
- All peers must be running the new genesis
- Check fork ID in handshake: `0x823f8537`
- Update bootstrap/seed nodes if needed

## Frequently Asked Questions

### Q: Will my wallet addresses change?
**A**: No, wallet addresses and private keys are preserved. Only on-chain balances are lost.

### Q: Can I keep my mining rewards?
**A**: No, all balances are reset to zero. The premine allocations in the new genesis are the only initial balances.

### Q: Will smart contracts need to be redeployed?
**A**: Yes, all contract state is wiped. Contracts must be redeployed after reset.

### Q: Can I run old and new chains simultaneously?
**A**: No, the fork ID prevents mixing. Nodes on different genesis cannot communicate.

### Q: What happens to pending transactions?
**A**: All pending transactions are lost. Mempool is cleared on reset.

### Q: How do I verify I'm on the correct chain?
**A**: Check genesis hash with `animica chain head` or in logs. It must match `0x6a27e93193020cd00fe429ef0ffac1c3a774268a589c2911ac396dd3cba2d242`.

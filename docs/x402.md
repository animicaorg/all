# x402 agent payments for Animica

**Status: implemented in `apps/x402-gateway/` — self-hosted Base-USDC
facilitator + paid product gateway. NOT yet deployed behind nginx/systemd
(a separate runbook step); everything is hard-gated behind
`ANM_X402_ENABLED=1`. Never uses any Coinbase service.**

## Why

x402 (`github.com/x402-foundation/x402`, spec v2 in force since 2025-12-09)
is the emerging default for agentic HTTP clients paying per call: the server
answers `402` with machine-readable payment requirements, the client pays
inside a request header, a facilitator verifies and settles on-chain, the
server serves and returns a receipt header. Animica sells compute, data and
randomness over HTTP; x402 lets agents buy those per-call without accounts
or API keys.

## Architecture (two separable layers)

```
agent ──402/PAYMENT-SIGNATURE──► gateway (src/server.js, 127.0.0.1:8742)
                                   │  products: qrng, bulk chain, priority
                                   │  inference (+dev echo); discovery at
                                   │  /x402 and /.well-known/x402
                                   ├──/verify /settle──► facilitator
                                   │       mode=self: src/facilitator-evm/
                                   │       (127.0.0.1:8743, Base mainnet
                                   │        USDC, EIP-3009 gasless settle)
                                   │       mode=remote: any §7-compatible
                                   │       facilitator URL (e.g. PayAI)
                                   └──reads──► local Animica node RPC
                                              (127.0.0.1:8545/rpc only)
```

* **Gateway** (`src/server.js` + `src/paywall.js` + `src/products/`):
  402 handling on both wire generations (v2 headers + v1 body/X-PAYMENT),
  tamper-proof requirement matching, product registry, availability gating,
  idempotency, signed failure receipts, metrics, structured logs.
* **Facilitator** (`src/facilitator-evm/`): verifies EIP-3009
  `transferWithAuthorization` payloads against the LIVE-verified Base
  mainnet USDC domain (`{name: "USD Coin", version: "2"}`, contract
  `0x833589fCD6eDb6E08f4c7C32D4f71b54bdA02913`, chain 8453), settles with
  its own funded key (gasless for the payer), confirms receipts
  (status + `AuthorizationUsed` + `Transfer` log match + N confirmations),
  and enforces replay protection in a persistent better-sqlite3 ledger —
  the UNIQUE `authorization_hash` is the double-settle arbiter, and crash
  recovery resolves in-flight settlements from chain truth before any
  rebroadcast. A tx merely submitted to RPC is never treated as settled.

The facilitator wallet can ONLY spend its own ETH on gas (bounded by
per-settlement gas caps, a fee-per-gas cap and an optional daily budget
breaker) and broadcast user-signed USDC authorizations whose amount and
destination it cannot alter. It should hold gas ETH only — revenue lands
directly at `X402_SETTLEMENT_ADDRESS`, which needs no hot key at all.
Customers sign locally; no user key ever reaches Animica.

## Payment flow

1. Request a paid route with no payment → `402` with `PAYMENT-REQUIRED`
   (v2, base64 JSON) and a v1-rendered JSON body. The offer's `accepts`
   carries `scheme: exact`, `network: eip155:8453`, the atomic USDC amount,
   `payTo` from server config, and `extra: {name: "USD Coin", version: "2"}`.
2. Client signs an EIP-3009 authorization locally and retries with
   `PAYMENT-SIGNATURE` (or v1 `X-PAYMENT`).
3. Gateway validates params → checks product availability → matches the
   echoed terms against its OWN offer → facilitator `/verify`.
4. Settlement and execution order is per product (below); success returns
   `200` + `PAYMENT-RESPONSE` (settlement receipt incl. the Base tx hash).

Execution order:

* **execute-then-settle** (qrng, echo): the resource is produced FIRST — a
  failure charges nobody; a failed settlement withholds the resource.
* **settle-then-execute** (bulk chain, inference): a mandatory readiness
  re-check runs immediately before settlement, then settle, then execute
  with one bounded retry. If the downstream still fails, the payer gets a
  **signed error receipt** and an incident row is opened (below).

## Products

Discovery: `GET https://…/x402` (and `/.well-known/x402`) returns
`{name, network, asset, products: [{id, path, price, description,
available, outputSchema…}]}` with **live** `available` flags — an
unavailable product never issues a 402.

### qrng — verifiable randomness, $0.01 (`X402_QRNG_PRICE_USDC`)

`GET /x402/qrng/draw?bytes=32` (or `POST /x402/qrng`). Wraps the node's
real `rand.quantumRandomBytes`: random bytes + entropy-health report +
signed digest attestation, all passed through verbatim. The gateway
enforces `health.passed` itself (the RPC never fails closed) and probes the
actual randomness surface before requesting payment.

Verify a draw (the rule the response's `verification` block states):

```js
// digest check: sha3_256 from the repo's dependency-free verifier
const { sha3_256 } = require('randomness/beacon_api/static/verify.js');
const bytes = Buffer.from(res.randomness, 'hex');
assert(Buffer.from(sha3_256(bytes)).toString('hex') === res.attestation.digest_hex);
// signature check: ed25519 over the RAW digest bytes
const { verify } = require('node:crypto');
// verify ed25519(public_key_hex, message = digest bytes, signature_hex)
```

Honesty: today the node's source is `software-fallback` (os.urandom) with a
software ed25519 signer, so `source.is_quantum: false` and
`attested: false` everywhere. The product is "verifiable randomness,
quantum-attested when hardware providers are connected" — the fields state
the truth, and the free `rand.*` RPC surface stays free (the $0.01 buys
packaging, health gating, attestation plumbing and the receipt). The
client-recomputable beacon+draw lane (`animica beacon serve` sidecar) is
the documented upgrade path once deployed.

### bulk_chain — bulk chain data, $0.05 (`X402_BULK_CHAIN_PRICE_USDC`)

```
GET /x402/chain/blocks?from=70000&count=500            # NDJSON block export
GET /x402/chain/transactions?from=70000&to=70999&address=anim1…&format=json
GET /x402/chain/export?type=blocks&from=…              # umbrella route
```

* Hard caps, enforced **before** payment where derivable from params:
  ≤1,000 blocks/window, ≤10,000 tx rows, byte + execution-time budgets.
  Mid-flight budget hits truncate at a block boundary with
  `summary.next_cursor` (= the first unconsumed height — feed it back as
  `from`). A fetch failure is the resume point, never a skipped hole.
* Exports pin to `head − 6` so they can't straddle a reorg; the pinned head
  rides in the NDJSON meta line. Amounts are **decimal strings in nANM**
  (values already exceed 2^53 — never `JSON.parse` them into floats).
* `Accept-Encoding: gzip` honored (~15x on block exports).
  The free per-block explorer/RPC APIs are unaffected — the paid path reads
  the loopback node in polite 100-block batches, single-flight.

### priority_inference — $0.10 (`X402_INFERENCE_PRICE_USDC`), DISABLED by default

`POST /x402/v1/chat/completions` (OpenAI-compatible, `stream:false` only).
Gated twice, per the capacity policy:

1. `PRIORITY_INFERENCE_ENABLED=1` (operator flag; ships as `0`), AND
2. live capacity ≥ `PRIORITY_INFERENCE_MIN_SERVING_WORKERS` (default 2),
   measured by polling `aicf.workerStatus` for the wallets in
   `X402_INFERENCE_WORKER_WALLETS` — set it to the SAME list as the chat
   bridge's `BRIDGE_KNOWN_WORKER_WALLETS`, since a worker the router can't
   route to must not be sold. A worker counts when `registered`,
   `last_seen ≤ 5 min` and serving `X402_INFERENCE_TIER` (default
   `standard`). Stale probes fail closed.

Below the floor: catalog says `available: false`, the endpoint answers a
clear `503 {"error":"priority_inference_unavailable","serving_workers":N,
"required":M}`, and **no 402 is ever issued** — payment is never taken for
a service known unavailable. Capacity is re-checked immediately before
settlement; a drop between the 402 and the paid retry refuses at zero cost
to the payer.

What paid honestly adds over the free `animica.dev/v1`: capacity-gated
admission, direct-to-bridge routing with **no per-IP rate limit** (free
tier: 30 req/min/IP through public nginx), a 180 s request budget sized for
real community-GPU latency, and the failure-receipt guarantee below. What
it does NOT add yet: reserved capacity or exclusive models — the same
workers serve both lanes, which is exactly why the gate exists.

### echo — $0.005, development only

`/x402/paid/echo` is the settlement smoke test. `X402_ENV=production`
disables it (in both `src/server.js` and `demo-server.js`) unless
`X402_ENABLE_ECHO=1`.

## Payment-then-service failure policy

Settle-first products that fail downstream AFTER settlement (bounded retry
exhausted) answer `502` with:

```json
{ "error": "paid_service_failed", "incident_id": "inc_…",
  "receipt": { "receipt_version": 1, "alg": "HMAC-SHA256", "key_id": "…",
    "ts": 1786755600, "payment_id": "0x<settlement tx>", "payment_fingerprint": "…",
    "resource": "/x402/chain/blocks", "product": "bulk_chain",
    "error": "…", "amount_atomic": "50000", "asset": "0x8335…2913",
    "network": "eip155:8453", "payer": "0x…", "signature": "…" } }
```

The receipt is HMAC-SHA256 (`X402_RECEIPT_HMAC_KEY`, canonical-JSON body)
over the settled payment's identifiers; the same data lands in the
gateway's `incidents` table (`open → refunded|resolved`) for the operator.
A transport failure DURING settlement (outcome unknown) withholds the
resource, answers 402 and opens a `settle_unknown` incident for
reconciliation against the facilitator DB + chain.

## Idempotency

Send `Idempotency-Key: <your key>` with a paid request. The gateway stores
`(key, payment fingerprint) → delivered response`; a retry carrying the
same payment payload and key replays the stored result (marked
`idempotent-replay: true`, settlement header included) with no facilitator
round-trip — a client can never be double-charged for a network hiccup.
Failed settlements store nothing (the payer kept their money; the retry
runs for real). Oversize bodies replay as a deterministic status reference.

## Operator CLI

```
apps/x402-gateway/bin/animica-x402 settlements list --status failed
animica-x402 payment get pay_… | <auth hash> | <tx hash>
animica-x402 revenue --since 24h          # settled sums per product
animica-x402 reconcile                    # settled rows vs chain receipts
animica-x402 gas report --since 7d        # incl. OP-stack L1 data fees
animica-x402 incidents list --status open
animica-x402 incidents resolve inc_… --status refunded
```

Local DBs only (`X402_DB_PATH`, `X402_GATEWAY_DB_PATH`); `reconcile` needs
`X402_RPC_URL` and flags any settled row whose on-chain receipt is missing
or mismatched (exit code 1). Metrics: `x402_settlements_total`,
`x402_settlement_failures_total`, `x402_replays_rejected_total`,
`x402_gas_spent_wei`, `x402_revenue_usdc`, `x402_payment_latency_seconds`,
`x402_idempotent_replays_total`, `x402_incidents_total`,
`x402_inference_serving_workers` on the loopback `/metrics` endpoints.

## Configuration

Every variable is documented in
[`apps/x402-gateway/.env.example`](../apps/x402-gateway/README.md) — copy
to a root-owned 0600 file (e.g. `/etc/animica-x402.env`); no secret is ever
committed. Startup is fail-closed: contradictions (chain id vs network,
non-allowlisted asset, malformed key, garbage price) refuse to boot.
Facilitator choice: `X402_FACILITATOR_MODE=self` (production goal, no
third party) or `remote` + `X402_FACILITATOR_URL` for any §7-compatible
facilitator (e.g. PayAI) — the gateway/product layer is identical either
way, and migration is a config change plus draining in-flight settlements.

## Deployment state

The live `animica-x402.service` currently runs the demo entry
(`src/demo-server.js`, 127.0.0.1:4656, `animica.dev/x402/` via nginx).
Promoting `src/server.js` + the self-hosted facilitator (systemd units,
nginx location, funded facilitator key, `X402_RECEIPT_HMAC_KEY`, real
`X402_SETTLEMENT_ADDRESS`) is a separate reviewed runbook step, after which
a real Base settlement must be observed end-to-end and reconciled with
`animica-x402 reconcile`.

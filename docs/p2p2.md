# P2P2 Protocol Documentation

## Overview

P2P2 is a complete rewrite of the Animica P2P networking stack designed for production reliability. It fixes critical sync issues ("missing parent", stuck at genesis, stalled sync) through clean architecture and robust error handling.

## Architecture

```
┌─────────────────────────────────────────────────────┐
│                   P2P2 Service                      │
├─────────────────────────────────────────────────────┤
│                                                     │
│  ┌──────────────┐  ┌──────────────┐  ┌──────────┐ │
│  │   Transport  │  │ Peer Manager │  │  Gossip  │ │
│  │  (TCP+Frame) │  │ (Slots+Score)│  │(Inv/Get) │ │
│  └──────────────┘  └──────────────┘  └──────────┘ │
│                                                     │
│  ┌──────────────────────────────────────────────┐  │
│  │         Sync Manager                         │  │
│  │  ┌─────────────┐    ┌────────────────────┐  │  │
│  │  │ Headers Sync│ -> │   Blocks Sync      │  │  │
│  │  │  (Locator)  │    │ (Orphan Pool+Fill) │  │  │
│  │  └─────────────┘    └────────────────────┘  │  │
│  └──────────────────────────────────────────────┘  │
│                                                     │
│  ┌──────────────────────────────────────────────┐  │
│  │           Storage Adapter                    │  │
│  │        (to existing block_db)                │  │
│  └──────────────────────────────────────────────┘  │
└─────────────────────────────────────────────────────┘
```

## Key Components

### Transport Layer (`transport/`)
- **TCP connections** with framing: `[u32 length][CBOR payload]`
- **Backpressure**: Bounded buffers prevent memory exhaustion
- **Reconnection**: Exponential backoff on failures
- **Timeouts**: Read/write timeouts prevent hanging

### Protocol (`protocol.py`)
- **CBOR encoding**: Deterministic, canonical serialization
- **Message types**: HELLO, PING/PONG, INV/GETDATA, GETHEADERS/HEADERS, BLOCK, TX
- **Handshake**: Verify network_id, chain_id, genesis_hash
- **Services bitfield**: SYNC, TX_GOSSIP, SNAPSHOT, MINING

### Peer Management (`peer/`, `peermanager.py`)
- **Slot management**: Configurable inbound/outbound limits
- **Scoring**: Increase for good behavior, decrease for bad
- **Banning**: Automatic ban when score < -10
- **Rate limiting**: Token buckets per message type
- **Persistent store**: Remember good peers across restarts

### Gossip (`gossip.py`)
- **Bitcoin-style inv/getdata**: Never push unsolicited data
- **Deduplication**: LRU caches for seen blocks/txs
- **Rate limits**: Per-peer token buckets
- **Penalties**: Bad messages reduce peer score

### Sync Manager (`sync/`)

#### Headers Sync (`sync/headers.py`)
- **Locator-based**: Build exponential backoff locator
- **Batch fetching**: Request up to 2000 headers at once
- **Validation**: Check parent chain linkage
- **Storage**: Persist headers incrementally

#### Blocks Sync (`sync/blocks.py`) **[CRITICAL FIX]**
- **Height-ordered requests**: Request blocks in strict height order
- **Orphan pool**: Blocks arriving before parent are stored
- **Parent backfill**: Automatically request missing parents (rate-limited)
- **Cascade attachment**: When parent arrives, recursively attach descendants
- **Reorg handling**: Switch to best chain without losing downloaded blocks

**Orphan Pool Details:**
```
Block arrives -> Has parent?
                   YES -> Store block
                          -> Check for orphans waiting on this block
                          -> Attach and cascade
                   NO  -> Add to orphan pool
                       -> Request parent (with rate limiting)
                       -> Wait for parent to arrive
```

## Protocol Messages

### Handshake
```json
{
  "type": "hello",
  "payload": {
    "node_id": "stable-pubkey-derived-id",
    "network_id": "mainnet",
    "chain_id": 1,
    "genesis_hash": "0xabc...",
    "protocol_version": 1,
    "services": 3,  // SYNC | TX_GOSSIP
    "listen_addrs": ["1.2.3.4:9333"],
    "best_height": 12345,
    "best_hash": "0xdef..."
  }
}
```

### Gossip
```json
// Advertise
{"type": "inv", "payload": {"items": [{"type": "block", "hash": "0x..."}]}}

// Request
{"type": "getdata", "payload": {"items": [{"type": "block", "hash": "0x..."}]}}

// Deliver
{"type": "block", "payload": {"hash": "0x...", ...}}
```

### Sync
```json
// Request headers
{
  "type": "getheaders",
  "id": "request-123",
  "payload": {
    "locator": ["0xabc...", "0xdef...", ...],
    "stop": null,
    "limit": 2000
  }
}

// Response
{
  "type": "headers",
  "id": "request-123",
  "payload": {
    "headers": [{...}, {...}, ...]
  }
}
```

## Configuration

### Environment Variables
- `P2P2_LISTEN_HOST`: Listen address (default: `0.0.0.0`)
- `P2P2_LISTEN_PORT`: Listen port (default: `9333`)
- `P2P2_MAX_INBOUND`: Max inbound peers (default: `50`)
- `P2P2_MAX_OUTBOUND`: Max outbound peers (default: `20`)
- `P2P2_DATA_DIR`: Data directory for peer store

### Code Configuration
```python
from p2p2.service import P2PService

service = P2PService(
    node_id="your-node-id",
    network_id="mainnet",
    chain_id=1,
    genesis_hash="0xabc...",
    listen_host="0.0.0.0",
    listen_port=9333,
    data_dir="/path/to/data",
    block_db=block_db,  # Existing storage
    state_db=state_db,
)

await service.start()
```

## Sync Flow Example

1. **Connect to seed nodes**
2. **Handshake** (verify network/chain/genesis)
3. **Headers sync**:
   - Build locator from current head
   - Send GETHEADERS
   - Receive HEADERS batch
   - Store headers
   - Repeat until at peer's tip
4. **Blocks sync**:
   - Compute next window (e.g., heights 100-600)
   - Derive expected block hashes from headers
   - Send GETDATA for blocks
   - Receive blocks (may arrive out of order)
   - If parent missing -> add to orphan pool
   - If parent exists -> store block, cascade orphans
   - Repeat until fully synced
5. **Stay at tip** via gossip:
   - Peers send INV for new blocks
   - We send GETDATA
   - Receive and store blocks

## Troubleshooting

### Stuck at Genesis
- Check: `animica peer list` - do you have connected peers?
- Check: `animica node status` - is sync running?
- Check logs for handshake errors (network/chain mismatch)

### Missing Parent Errors
- Check: `animica peer debug` - orphan pool size
- If orphan pool growing: parent backfill is working
- If orphan pool constant: may need to rotate peer
- Check inflight blocks - should be non-zero during sync

### Sync Stalled
- Check: `animica node status` - when was last progress?
- Check peer scores - low scores indicate bad peers
- Rotate to different peer
- Check orphan pool - may need manual intervention if huge

## Performance Tuning

### Headers Sync
- `batch_size`: Headers per request (default: 2000)
- `max_concurrent_requests`: Parallel requests (default: 3)

### Blocks Sync
- `window_size`: Blocks to request in parallel (default: 500)
- `max_orphans`: Max orphan pool size (default: 10000)
- `orphan_ttl`: Orphan expiry (default: 600s)

### Rate Limiting
- `inv_rate`: Inv messages per second per peer (default: 10)
- `getdata_rate`: Getdata messages per second (default: 20)
- `msg_rate`: General messages per second (default: 50)

## Differences from P2P v1

| Feature | P2P v1 | P2P2 |
|---------|--------|------|
| Framing | Custom | [u32 len][CBOR] |
| Encoding | Mix of JSON/msgpack | CBOR only |
| Orphan handling | Fatal error | Pool + backfill |
| Peer scoring | Basic | Comprehensive |
| Rate limiting | Minimal | Per-type buckets |
| Sync strategy | Block-first | Headers-first |
| Reorg handling | Unclear | Explicit |

## Migration from P2P v1

P2P2 is wire-incompatible with P2P v1 (different framing/encoding). Deploy requires:
1. Coordinated upgrade across network
2. Or: Run both temporarily, deprecate v1

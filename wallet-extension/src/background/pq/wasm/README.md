# Dilithium3 WASM Backend for Wallet Extension

This directory contains the PQ cryptography WASM modules for the Animica wallet extension.

## Files

- `dilithium3.c` - C reference implementation of ML-DSA-65 (Dilithium3)
- `sphincs_shake_128s.c` - SPHINCS+ SHAKE-128s implementation (placeholder)
- `loader.ts` - JavaScript/TypeScript loader for WASM modules
- `Makefile` - Build system for compiling C to WASM
- `dilithium3.wasm` - Compiled WASM module (generated)
- `sphincs_shake_128s.wasm` - Compiled WASM module (generated)

## Building WASM Modules

### Prerequisites

1. Install Emscripten SDK:
```bash
git clone https://github.com/emscripten-core/emsdk.git
cd emsdk
./emsdk install latest
./emsdk activate latest
source ./emsdk_env.sh
```

2. Verify installation:
```bash
emcc --version
```

### Build Commands

```bash
# Build all WASM modules
make

# Clean build artifacts
make clean

# Show help
make help
```

### Output

The build process generates:
- `dilithium3.wasm` - WebAssembly binary module
- `dilithium3.mjs` - ES6 module loader (generated by Emscripten)

## Alternative: TypeScript Implementation

If you don't have Emscripten or prefer a pure TypeScript solution, you can use the TypeScript port included in this package. The `loader.ts` will automatically fall back to dev implementations when WASM is not available.

## Architecture

The wallet extension uses a layered approach for PQ cryptography:

1. **WASM Backend (Preferred)**: Fast C implementation compiled to WASM
2. **Dev Fallback**: Deterministic TypeScript implementation for development
3. **Graceful Degradation**: Automatically selects best available backend

### WASM C API

The C implementation exports these functions:

```c
// Constants
const uint32_t PK_BYTES = 1952;
const uint32_t SK_BYTES = 4000;
const uint32_t SIG_BYTES = 3293;

// Key generation
int keypair_from_seed(const uint8_t *seed, size_t seed_len, uint8_t *pk, uint8_t *sk);

// Signing
int sign(const uint8_t *msg, size_t msg_len, const uint8_t *sk, uint8_t *sig);

// Verification
int verify(const uint8_t *msg, size_t msg_len, const uint8_t *pk, const uint8_t *sig);
```

### TypeScript Wrapper

The `loader.ts` module wraps the C ABI into ergonomic async functions:

```typescript
export interface DilithiumBindings {
  ALG_ID: 'Dilithium3';
  PK_BYTES: number;
  SK_BYTES: number;
  SIG_BYTES: number;
  keypairFromSeed(seed: Uint8Array): Promise<{ publicKey: Uint8Array; secretKey: Uint8Array }>;
  sign(message: Uint8Array, secretKey: Uint8Array): Promise<Uint8Array>;
  verify(message: Uint8Array, signature: Uint8Array, publicKey: Uint8Array): Promise<boolean>;
}
```

## Security Notes

⚠️ **WARNING**: This is a REFERENCE implementation for development and testing.

For production use, you MUST:
1. Replace with a fully validated ML-DSA-65 implementation
2. Undergo security audit
3. Validate against NIST test vectors
4. Use constant-time operations to prevent side-channel attacks

The current implementation uses SHAKE-256 (Keccak) for deterministic outputs but does NOT implement the full Dilithium lattice-based signature scheme.

## Testing

The WASM modules are tested via the wallet extension test suite:

```bash
cd /path/to/wallet-extension
pnpm test
```

Test vectors are generated from the Python reference implementation to ensure compatibility.

## Troubleshooting

### WASM fails to load

1. Check browser console for errors
2. Verify WASM file is present and not corrupted
3. Check Content Security Policy allows WASM
4. Ensure WebAssembly is supported in the browser

### Dev fallback always used

1. Set `VITE_PQ_DEV_FALLBACK=0` to disable fallback
2. Check that WASM file exists at expected path
3. Verify WASM module exports match expected C ABI
4. Check browser compatibility
